## Anti-Patterns Verdict

**LLM assessment**: This does not read as AI-generated slop. Zero hard-ban tells surfaced: no gradient text, no ghost-card (1px border + wide soft shadow), no over-rounded cards (radius scale is 10–16px, on-brand), no sketchy SVG, no stripe/repeating-gradient backgrounds, no decorative grid overlay, no eyebrow-on-every-section, no numbered 01/02/03 scaffolding, no hero-metric template. The Operational Red is used sparingly (primary actions, active nav, icons) — the One Voice Rule is respected. The product-register slop test ("would a Linear/Stripe-fluent user trust this?") is mostly passed; the failures are strangeness-from-inconsistency, not strangeness-from-decoration.

## Overall Impression

Pulso's dashboard is a genuinely well-engineered operational surface that has outgrown its own conventions. The foundations are strong: a committed OKLCH palette with proper dark mode, a shared `PageHeader`/`PageContainer`/`KpiCard`/`EmptyState` vocabulary, Suspense skeletons on the home page, and role-based nav filtering. The single biggest opportunity is **consistency drift**: the home dashboard, the inventory page, and the compliance page were built with three different data-fetching strategies, two different header systems, two different title sizes, and two different padding models. A user fluent in best-in-class tools would trust the parts but pause at the seams between them.

## What's Working

1. **Flat, tonal, on-brand color system.** `globals.css` defines the full OKLCH ramp with warm-tinted neutrals (hue 85) and a proper dark-mode pair. Operational Red stays under ~10% on every page I read. No shadows-as-decoration, no glassmorphism. This is the DESIGN.md "Flat-By-Default" rule actually enforced in code.

2. **Shared page vocabulary where used.** `PageHeader` + `PageContainer` + `KpiCard` + `EmptyState` are well-built, composable, and correctly handle responsive collapse (icon hidden on mobile, `flex-wrap` on title+badge). The inventory page is the model citizen: `PageContainer` → `PageHeader` (with branch select + primary action) → "Actualizado" tooltip → KPIs → alerts → "Empezar el día" daily-actions strip. That page alone is a template for the rest.

3. **Loading and empty states exist as first-class concerns.** Home page wraps every async section in `<Suspense fallback={<...Skeleton/>}>`. `EmptyState` carries icon + title + description + action. The recent-workflows table has a real empty state with search-aware copy ("No se encontraron flujos coincidentes" vs "No hay actividad reciente"). Few dashboards this size bother.

## Priority Issues

### [P1] Muted-foreground fails AA contrast for secondary text
- **What**: `--muted-foreground: oklch(0.50 0.01 85)` on white computes to ~4.0:1, under the 4.5:1 AA floor for normal-size text. It's used for descriptions (`text-sm text-muted-foreground`), table metadata, the "Actualizado" timestamp, tooltips, and placeholder copy across the surface.
- **Why it matters**: Secondary text is where HORECA managers actually read the detail ("Registra la mercancía que llega del proveedor", "Sin asignar", relative timestamps). Borderline-low contrast is the single biggest reason operational dashboards feel hard to read on the tablet/bright-kitchen screens the brief targets. Also blocks Sam (screen-reader/low-vision persona).
- **Fix**: Darken `--muted-foreground` to ~`oklch(0.45 0.012 85)` light / `oklch(0.62 0.01 85)` dark and re-measure until ≥4.5:1. Keep `--border` lighter; only the text token moves.
- **Suggested command**: `$impeccable audit`

### [P1] Three coexisting data-fetching architectures
- **What**: (a) Server Component + direct `db` queries + Suspense (home `page.tsx`, `labor/page.tsx`); (b) Client Component + TanStack-style `useDashboard()` hook with `isLoading/isError/refetch` (inventory); (c) Client Component + raw `useEffect` + `fetch("/api/...")` with manual `useState` and no error UI (`compliance/page.tsx`, `components/dashboard/executive-summary.tsx`). Same product, three strategies.
- **Why it matters**: Pattern (c) silently fails — `ExecutiveSummary` does `setData(null)` on catch and `if (!data) return null`, so a fetch error renders nothing with no recovery; compliance only `console.error`s. Users see a blank section and don't know why. It also duplicates server-side auth/tenant logic client-side and forfeits Suspense streaming. Heuristic 4 (consistency) and 9 (error recovery) both break here.
- **Fix**: Pick one client strategy — the `useDashboard()` hook pattern from inventory (with `isError` + `onRetry`) — and migrate `compliance/page.tsx` and `executive-summary.tsx` to it. Prefer Server Components for read-only data (the home-page pattern) wherever the data doesn't need client interactivity. Delete the raw-`useEffect`+`fetch` pattern.
- **Suggested command**: `$impeccable harden`

### [P1] Two header/title/container systems (home vs. sections)
- **What**: Section pages use `PageContainer` (`max-w-7xl mx-auto p-4 lg:p-8`) + `PageHeader` (`text-xl sm:text-2xl font-bold`). The home dashboard (`app/dashboard/page.tsx`) rolls its own `border-b bg-card` header with `text-3xl font-bold` and its own `max-w-7xl mx-auto px-4 lg:px-6 py-6` container. Then the layout wraps children in `p-4 pt-0 bg-muted/20`, so section pages get **double padding** (layout `p-4` + `PageContainer` `p-4 lg:p-8`), and the home page gets `p-4` + `px-4 lg:px-6`.
- **Why it matters**: The home page is the first screen every owner sees and the one place the brand should feel unified; instead it visually diverges from every section behind it (different title size, different container, different gutter math). The doubled padding narrows the content rail on mobile and creates an inconsistent rhythm between top-level and drill-down pages. Heuristic 4 and 8.
- **Fix**: Make the home page use `PageContainer` + `PageHeader` (with `title={t("title")}`, `description={t("subtitle")}`, `actions={<DashboardFilters/><ComplianceReportGenerator/>}`). Remove the layout's `p-4 pt-0` (let `PageContainer` own the padding) or remove `PageContainer`'s padding and let the layout own it — don't both. One padding owner.
- **Suggested command**: `$impeccable layout`

### [P2] Semantic color drift: raw Tailwind colors in status badges
- **What**: `recent-workflows-table.tsx` uses `bg-emerald-500/10 text-emerald-600 dark:text-emerald-400` and `bg-blue-500/10 text-blue-600` for status badges; the inventory "Actualizado" dot uses `bg-emerald-500`. DESIGN.md defines `--success`, `--info`, `--warning`, `--destructive` semantic tokens that are unused here.
- **Why it matters**: The semantic tokens are tuned for both themes; the raw Tailwind values are patched with `dark:` overrides per-use, which doesn't scale. Status color is exactly where "one platform, one truth" must hold — a green that means "Completado" should be the same green everywhere. Heuristic 4.
- **Fix**: Replace `emerald-500/600/400` → `success`/`success-foreground` tokens and `blue-500/600/400` → `info`/`info-foreground`. Add `bg-success/10 text-success border-success/20` badge variants in the Badge component so this stops being per-component CSS.
- **Suggested command**: `$impeccable colorize`

### [P2] Sub-floor type: 10–11px text below the 12px Label floor
- **What**: Detector flagged `audit/page.tsx:840` (10px) and `profile/onboarding/page.tsx:171` (11px), both below the DESIGN.md Label step (0.75rem = 12px).
- **Why it matters**: Below 12px, text fails to read on the tablet/bright-ambient screens the primary audience uses, and falls outside the documented type ramp (the ramp exists for exactly this reason). Heuristic 8.
- **Fix**: Bump both to `text-xs` (12px). If the 10px is intentional dense data, add a documented `--text-2xs` token to the design system rather than ad-hoc literals.
- **Suggested command**: `$impeccable typeset`

### [P2] Compliance page: 7-tab IA at the cognitive-load edge
- **What**: `compliance/page.tsx` renders a `grid-cols-3 lg:grid-cols-7` TabsList with 7 top-level tabs (Dashboard, Corporativa, NOM-251, NOM-035, IMSS, Nómina, Info), each icon+text. On mobile it wraps to 3-col rows of mixed heights.
- **Why it matters**: 7 visible options at one decision point exceeds the ≤5 ideal and the working-memory ≤4 bucket; a manager scanning "where do I generate my IMSS report?" has to map 7 coequal tabs. The mobile wrap produces uneven rows. Heuristics 7 and 8.
- **Fix**: Group into ≤4 primary tabs (Dashboard, NOM-251, NOM-035, IMSS/Nómina) and sink IMSS/Nómina/Info into a "Más" overflow or a sub-nav. Or move to a left sub-sidebar that lists the 7 as a vertical rail (template: Inventario's grouped submenu).
- **Suggested command**: `$impeccable layout`

### [P2] Inconsistent error/loading treatment across the surface
- **What**: Inventory passes `isError` + `onRetry` to its sub-components (good). ExecutiveSummary has an `animate-pulse` skeleton but silently nulls on error. Compliance `useEffect`-fetch has no loading skeleton at all. Home page uses Suspense skeletons (good). The labor page's "no company" state is hand-rolled inline instead of using the shared `EmptyState`.
- **Why it matters**: Users can't tell "loading" from "broken" from "empty" on the pages that don't distinguish them. Heuristics 1 and 9.
- **Fix**: Standardize on `EmptyState` for empty, the existing `*Skeleton` components for loading, and an `ErrorState` (there's a `components/shared/error-state.tsx` — verify it's wired everywhere) with retry for error. Every async section should render exactly one of the three.
- **Suggested command**: `$impeccable harden`

## Persona Red Flags

**Alex — Impatient Power User**: No keyboard shortcuts anywhere (tab order is default, no `cmd+k` command palette, no `/`-focus search outside the recent-workflows table). The recent-workflows table search is good but local to one component; a 15-branch owner will want a global fast-switcher. One-item-at-a-time patterns dominate where bulk would be natural (e.g., stock-count adjustments, approving multiple shift changes). The 24-item Inventario submenu forces Alex to memorize a 4-group mental map instead of typing "merma" and jumping. High risk of Alex reaching for a spreadsheet because it's faster.

**Sam — Accessibility-Dependent User**: `tab` order is not verified and focus indicators are present (`focus-visible:ring-2 ring-ring`) but only where explicitly added — the inventory daily-action cards have it, most card hovers don't. Status is conveyed by color alone in several places (emerald = Completado, blue = En Progreso) with an icon, which is okay, but the score color (`text-emerald-600` / `text-amber-600` / `text-destructive`) carries meaning with no text alternative. Most critically, `--muted-foreground` at ~4:1 fails the 4.5:1 floor Sam relies on. No `aria-live` on the silently-nulling ExecutiveSummary. Will lose state changes.

**Mariana — Owner of a 3–15 branch restaurant group** (project persona, from PRODUCT.md audience + the "brief matutino de Mariana" comment in `inventory/page.tsx`): Mariana opens the home dashboard for her morning cross-branch brief. The page stacks 8 sections vertically — announcements, KPIs, executive summary, pending actions, KPI summary, charts, alert distribution, recent activity — with no singular "what needs my attention right now" affordance. She has to scroll past announcements and a KPI grid before reaching `PendingRemediationActionsCard`, which is arguably the most owner-relevant block. The `branchFilter="all"` rollup on inventory is good for her brief, but the home dashboard's filters (`DashboardFilters`) and the inventory branch select are two different filter UIs for the same conceptual scope. Red flag: the single-pane-of-glass promise is diluted by a long scroll and inconsistent scope controls.

## Minor Observations

- `border-b-2` accent on rounded cards (3 files) — the bottom-edge sibling of the banned side stripe. Remove or replace with a full border / background tint.
- `PageHeader`'s `h1` doesn't set `text-wrap: balance` (DESIGN.md No-Orphan Rule). One CSS line.
- The compliance page title is the English string "Compliance" while every other page uses Spanish — likely an oversight; "Cumplimiento" is already used in the sidebar.
- The home page's "Pinned Announcements" badge uses `bg-primary/10 text-primary` (red) for every announcement type, regardless of `communicationType`. The type distinguishing is left to tiny label text.
- The recent-workflows table header uses `uppercase tracking-wider` on `text-xs` — reads as the tracked-eyebrow micro-pattern at the row level; fine in a table header but don't propagate it to section headings.
- `ExecutiveSummary` fetches client-side via `useEffect` while its parent (`app/dashboard/page.tsx`) is a Server Component already querying the DB directly. The executive summary could be fetched server-side and streamed via Suspense like the rest of the home page.

## Questions to Consider

- What if the home dashboard opened with the **one** thing that needs Mariana today (pending remediation / critical incidents) above the KPI grid, instead of after announcements and metrics?
- There are two filter UIs for the same scope (home `DashboardFilters` vs inventory branch `<Select>`). Could one scope control live in the header and propagate to every section?
- The 24-item Inventario submenu is comprehensive but unreadable. Would a command palette (`cmd+k`) let you collapse it to ~8 items and still be faster for Alex?
- Three data-fetching strategies is the real cost driver here. If you pick one, which pattern wins for read-heavy operational dashboards — Server Component + Suspense, or the `useDashboard()` hook?
