## Design Specificity Verdict

**Authored copy on an inherited skeleton.** The words are unmistakably Pulso: "Comando de Red", "Pulso en Vivo del Turno", "Matriz Operativa de Red", "Mesa de Excepciones", "Inocuidad & Frío", "Merma", "Frío NOM-251 · Sin registro / Sin lectura hoy". No generic admin can produce that sentence. But the structure is the standard admin shell — collapsible sidebar, breadcrumb, metric-tile row, card grid, data table — and the home page's composition order (tiles → alert panel → table → second card grid → table) would host any B2B product unchanged. Specificity currently lives in vocabulary and domain chips, not in composition.

**Deterministic scan.** The CLI detector (`detect.mjs`) found exactly one finding across 184 files: `text-[11px]` at `app/dashboard/branches/page.tsx:261`, off the DESIGN.md type ramp — the documented "Label-Floor Rule" violation, plus existing occurrences under `components/analytics/` and `components/finance/`. Re-run against `components/dashboard`, `components/shared`, `components/app-sidebar.tsx` and `app/dashboard/layout.tsx`: zero findings. The static net is narrow; the in-page detector found 20–44 nodes per page.

**Visual overlays.** Injection succeeded and the overlay is live in the browser (87 overlay nodes present, console group `[impeccable] 43 anti-patterns found` on `/dashboard/exceptions`). Aggregated per page: `/dashboard/exceptions` 44 nodes (nested-cards 23, cramped-padding 8, line-length 6, layout-transition 5, text-overflow 1, text-occlusion 1); `/dashboard` 34 nodes (nested-cards 25); `/dashboard/inventory` 20 nodes (nested-cards 8, text-overflow 6, layout-transition 5, line-length 1). The overlay caught structurally what the visual pass only felt: the cause of the low-density cards is card-inside-card nesting, and the sidebar animates layout on every page.

## Overall Impression

This is a product with a real voice and a real architecture, wrapped in screens that are too loud and too empty at the same time. The domain language and the branch-scope engineering are genuinely better than the category — `layout.tsx` documents a bug where the header said one branch while the server answered for the chain, and fixes it. But the surfaces that carry the product's promise are the weakest: `/dashboard/exceptions` (triage) shows three items per viewport for a 23-item queue, and `/dashboard/labor` prints `NaN%` where the compliance number should be.

The single biggest opportunity: **the home page answers "what is happening across the chain" five times and commits to no verdict.** One sentence, one dominant signal, everything else reachable instead of displayed, would fix hierarchy, density and cognitive load at once.

## What's Working

1. **Domain language that passes the specificity test.** "Mesa de Excepciones", "Merma", "Inocuidad & Frío", and a matrix column header reading "Frío NOM-251 / Sin registro / Sin lectura hoy". This is the product's moat and it is already in the UI.
2. **The severity model in `LivePulseBanner`.** It escalates on the union of four signals (openings, staffing, cold chain, alerts) and states the fact — "3 de 3 sucursales sin apertura a tiempo" — instead of an adjective. The code comment shows this was a deliberate correction of an earlier single-counter version. It is the one place the design reasons about truth rather than decoration.
3. **The scope architecture, and flat-by-default layering.** Cookie-backed branch scope with `pulso_branch_scope=all` distinguishing "I chose all" from "not chosen yet"; each home section wrapped in its own `SectionErrorBoundary`; zero unauthorized shadows on the sampled surfaces; both semantic `-text` variants (`--warning-text`, `--success-text`) exist with comments explaining why contrast on tinted fills needs them. axe-core: 0 violations, 41 passes.

## Priority Issues

### [P1] `NaN%` shipped as a compliance metric
- **What:** `/dashboard/labor` renders "Cumplimiento General: NaN%". `app/dashboard/labor/page.tsx:104` guards `weeklyStats?.totalSessions` but not `compliantSessions`, so `Number(undefined) / n * 100` → `NaN` → `Math.round(NaN)` → line 243 interpolates it. Line 105 (`onTimeRate`) has the identical shape and is one null away.
- **Why it matters:** This is the number that carries the product's core promise on the module that owns HR. An owner cannot tell whether compliance is 0, 100, or broken. It converts a trust asset into a credibility loss, and it is the one defect a customer will screenshot.
- **Fix:** Guard both operands (`Number(x || 0)`), and make `MetricCard` refuse to render a non-finite value — show "—" with a subtitle instead. Audit every `${...}%` interpolation in `app/dashboard/**` for the same pattern.
- **Suggested command:** `$impeccable harden`

### [P1] The triage screen cannot be triaged
- **What:** `/dashboard/exceptions` shows 3 exception cards per 900px viewport for a 23-item queue (~4,400px of scroll). Detector: 25 nested-card violations, 23 of them on exception cards; each card is one title + one clamped description + one button inside ~190px of mostly empty space. Six body strings run 109–119 chars/line. The five category filter cards clip their own descriptions via `line-clamp-1` (`app/dashboard/exceptions/page.tsx:192`), so the explanation of each category reads "Arqueos descuadrados, TPVs y...".
- **Why it matters:** A compliance queue is the one screen where scan-rate is the whole feature. Cutting 41% of a card's height and losing the category copy means the manager triages by scrolling, and stops reading the queue before item 10.
- **Fix:** Collapse the card to a dense row (severity, category, branch, age, one action) and move the description into a detail pane beside it — the two-column shape `/dashboard/finance` already uses. Un-clamp the filter descriptions to two lines or cut the copy to fit.
- **Suggested command:** `$impeccable distill`, then `$impeccable layout`

### [P1] Truncation is load-bearing throughout the surface
- **What:** In-page detector, `/dashboard/inventory`: the four "Empezar el día" quick-action descriptions clip 100px, 97px and 65px out of 242/239/207px sentences inside a 142px box. On every page the sidebar company label clips 29px ("Pulso HORECA Demo (ENTERPRISE)" at 188px in a 159px box). `PageHeader`'s h1 carries `truncate`.
- **Why it matters:** DESIGN.md bans exactly this ("Don't let text overflow its container. Test heading copy at every breakpoint"). The clipped strings are not decoration — they are the copy that explains what an action does. Replacing them with an ellipsis removes guidance and replaces it with a guess.
- **Fix:** Shorten the quick-action copy to fit its box, give the sidebar label an explicit two-line allowance or drop the plan suffix from the name, and remove `truncate` from the h1 in favour of a smaller clamp step.
- **Suggested command:** `$impeccable clarify`, then `$impeccable adapt`

### [P1] Every page animates layout, and the shell shifts on load
- **What:** The in-page detector returns the same 5 `layout-transition` warnings on `/dashboard`, `/dashboard/exceptions` and `/dashboard/inventory`: `transition: width` on `div.relative.w-(--sidebar-width)` and `div.fixed.inset-y-0`, `transition: margin` on the menu button — plus the dashboard layout's own `transition-[width,height]` on the header. Measured CLS: **0.18** (target < 0.1). TTFB 1,803ms, FCP 2,136ms, LCP resolving to a `<p>`, 453 hydrated components on the home route.
- **Why it matters:** Layout thrash on the sidebar is jank on every interaction in the product, and a 0.18 CLS on the first screen means the content moves while the owner is reading it. The skeleton-to-content swap also changes height, so the shift is self-inflicted.
- **Fix:** Animate `transform` or `grid-template-columns` instead of `width`/`margin`; give the Suspense fallbacks the same geometry as the loaded section so the swap costs zero layout.
- **Suggested command:** `$impeccable optimize`, then `$impeccable animate`

### [P2] Nine sections, ~85 links, three names per screen, five readings of one state
- **What:** The nav holds 9 top-level collapsible sections and ~85 destinations, two clicks minimum from anywhere. The same surface carries three names: sidebar "Excepciones & Riesgos" / breadcrumb "Excepciones" / H1 "Centro de Excepciones & Riesgos"; sidebar "Panel de Inventario" / breadcrumb "Inventario" / H1 "Gestión de Inventario". The home page states the same 3-branch condition five times (pulse banner, rush panel, matriz, 6 area cards, bitácora), and all six area cards wear an amber count badge, so the rush panel and the pulse banner's red pill make the same claim at the same weight.
- **Why it matters:** The product's fourth principle is "one platform, one truth" — but five renderings of one fact means the user has to decide which to believe. Equally weighted signals give the eye no entry point, which is the definition of a dashboard that gets ignored.
- **Fix:** One name per surface (H1 wins). Propagate `OPERAR / COMPRAR / ANALIZAR` grouping to all nine sections and reconsider whether all nine earn a top-level slot. On the home page, keep one verdict line and demote the rest to reachable detail. Reserve a single accent for the highest-severity state.
- **Suggested command:** `$impeccable distill`, then `$impeccable clarify`

## Persona Red Flags

**Alex (Power User)** — No keyboard shortcuts and no command palette anywhere in the shell; 85 links sit behind 9 closed accordions, so every destination costs an expand plus a click. `/dashboard/exceptions` holds 23 items with zero multi-select and zero bulk actions. The "A1+A" chip on `/dashboard/labor` looks like an accelerator and does nothing. "Actualizar" is a manual refresh on a page whose title claims "en tiempo real", with no auto-refresh and no last-updated timestamp. Measured: `get-session` 1.4–1.9s per call, `/dashboard/labor` `render: 8.7–18.6s`. **High abandonment risk.**

**Jordan (First-Timer)** — Two scope controls ("Sucursal: Todas", "Fecha: Todo el periodo") with nothing stating which governs the matrix versus the bitácora. Unexplained jargon everywhere: NOM-251, M17, LFT, Prime Cost, A1+A, Mesa de Excepciones, "Score de cumplimiento". "Fecha Operativa: 2026-10-16" renders a raw ISO date beside es-MX currency on the same card. Four severity words (Fatal / Crítico / Alto / Aviso) appear as badges with no legend while category badges reuse the same shapes in pink, purple and amber. The one place that would explain the categories — the filter-card descriptions — is clipped mid-sentence. And `NaN%` is unreadable as missing, zero, or broken. **Abandons at the first filter.**

**Sam (Accessibility)** — axe reports 0 violations and 41 passes on `/dashboard`, and the `-text` semantic variants are a real contrast fix. But axe also flags heading order as incomplete (moderate): the h2 "Salud Operativa por Áreas del Grupo" and the h3 "Actividad Reciente" could not be sequenced, and "Actividad Reciente" reads as a subsection of the wrong parent. Genuine sub-24px targets: "Ver mesa" at 62×16px and the matriz branch-name links ("Condesa", "Polanco", "Roma") at 20px tall, against WCAG 2.5.8's 24×24. Two React hydration mismatches fired on `/dashboard/exceptions` — React does not patch those up, so assistive navigation during the window acts on a tree already abandoned. Severity on the pulse dot and area cards is still carried by colour, though text accompanies it.

**Rosa (dueña de la cadena, 3–15 sucursales — project persona)** — Opens the dashboard between services on a tablet or phone with one question: *which branch needs me right now?* The answer is spread across five components with no verdict line. The number she'd trust most reads `NaN%`. Her queue opens on a "Fatal / INOCUIDAD" item dated `hace alrededor de 2 meses`, which teaches her the queue is not live. The page says it monitors "el turno" while both scope selectors say "Todas" and "Todo el periodo", so she cannot tell what window the numbers cover and discounts all of them. **The home page is 5,104px tall on her phone.**

**Mateo (gerente de sucursal, GERENTE fixed to one branch — project persona)** — Works on a phone, standing up, interrupted. His daily actions (Asistencia, Turnos, Breaks) sit in the third band of `/dashboard/labor`, below 12+ tiles and two rails. "Asistencia del Día 0% · Hoy: 0/0 empleados en turno" reads as failure rather than missing data. The "Empezar el día" cards clip exactly the 100px that would have told him what each action does. The bitácora table is 979px wide inside a 390px viewport, so "Iniciar" requires horizontal scrolling. His branch scope survives a reload (genuinely good) but his reading position does not.

## Minor Observations

- CLI vs in-page detector coverage gap: 1 static finding vs 20–44 in-page nodes per page. Do not read the static scan as coverage.
- `/dashboard/inventory`: the "SKUs de alto valor" card holds a single 862px-wide paragraph at ~123 chars/line (DESIGN.md caps body at 70ch) with an orphaned "Contar →" button floating in the empty half.
- `/dashboard/finance` puts its tab bar **above** the H1 while every other page puts sections below, and titles the page "Hoy" where the H1 pattern elsewhere is a descriptive noun phrase.
- `/dashboard/finance` renders two indefinite spinners ("Cargando bandeja operativa…", "Proyectando tesorería…") with no skeleton geometry, beside an empty state that has already resolved.
- The 6 area cards break their own structure: five show a metric value, Finanzas shows only "Sin excepciones abiertas"; and "Personal 0 ausencias" carries a badge of `1` while `/dashboard/exceptions` says "Personal & Turnos 1".
- No motion tokens exist in DESIGN.md, so `transition-colors`, `transition-all`, `transition-[width,height]` and `duration-200/300/500` are used ad hoc.
- `text-[11px]` from the static scan is a documented floor violation, not a one-off: `components/analytics/branch-qsr-scorecard.tsx` uses it 5 times and `components/finance/add-invoice-modal.tsx` at least twice.
- Dark mode was not verified this pass (no dark-mode capture route available in the browser batch surface).

## False Positives / Verified Non-Issues

- `text-occlusion` on all three pages is the overlay's own "line length too long" badge being covered by the h1 it anchors to — a detector self-artifact, not a product defect.
- A target-size count of 14 was mostly measurement artefact: the row-action anchors wrap a 32px `Button` while the inline `<a>` reports a 19px box. The genuine sub-24px targets are the plain text links named above.
- Header `scrollWidth 389` vs `clientWidth 375` at a 390px viewport is **not** content clipping — no child overflows. Not reported as a defect.

## Questions to Consider

- The home page answers "what is happening across the chain" five times. What would it look like if it answered once, in one sentence, and made everything else reachable rather than displayed?
- "Comando de Red en Vivo" sits beside "Fecha: Todo el periodo". Which is true? If the page is a live turno, why is its only time control an all-time scope?
- Nine sections, ~85 links: how many has a single owner opened in the last month? What would the nav look like holding only the six screens a dueña opens daily, with the rest behind search?
- Every exception is a full card holding one sentence. If the queue were a table and the "card" were the detail pane, what fraction of the scroll would remain?
- The promise is "pass regulatory audits without stress". A queue led by a two-month-old Fatal item and a compliance metric reading `NaN%` deliver the opposite. What is the smallest change that makes the first screen provably true?
