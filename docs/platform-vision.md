# Pulso — De Herramienta a Infraestructura Operacional

> **Documento de refundación estratégica**
>
> **Disparador:** El documento `consultoria-business-model.md` reveló accidentalmente que Pulso estaba posicionado como accesorio de una consultoría, no como la infraestructura central.
>
> **Corrección de rumbo:** Pulso no es una firma de consultoría con software. Pulso es una plataforma de inteligencia operacional. La consultoría es un acelerador de adopción, no el producto.
>
> **Fecha:** Julio 2026

---

## 0. El Diagnóstico Incómodo

El documento anterior de consultoría cometió un error estructural: **Pulso desaparecía de su propia historia.**

La narrativa era:

```
Consultor → usa Pulso → mejora restaurante
```

Pero debería ser:

```
Pulso → crea un sistema operativo → el consultor acelera la adopción
```

La diferencia no es semántica. Es existencial. Define si estamos construyendo una empresa de servicios o una empresa de tecnología.

**El test revelador:** Si quitas Pulso del documento de consultoría, el documento sigue funcionando. Eso significa que Pulso no es indispensable en la historia. Una consultora genérica podría usar Trello, Excel, o cualquier otra herramienta. Pulso era reemplazable en su propia narrativa.

## 1. Qué Estamos Realmente Construyendo

### No es software de gestión. Es infraestructura operacional.

| Vista equivocada | Vista correcta |
|------------------|----------------|
| Software para restaurantes | Sistema operativo para operaciones distribuidas |
| Módulos (compliance, inventario, laboral) | Capacidades (evidencia, trazabilidad, predicción) |
| Herramienta del consultor | Infraestructura que acumula inteligencia |
| Vender features | Vender una nueva capacidad organizacional |
| Silo HORECA | Primer vertical de una plataforma multi-industria |

### El paralelo correcto no es una consultora. Es Stripe.

Stripe no vende consultoría de pagos. Vende infraestructura de pagos. Después aparecen agencias, consultores, partners que implementan Stripe. Pero Stripe es la plataforma.

Pulso debería ser **la infraestructura operacional para negocios con ejecución distribuida.** Los consultores vienen después.

### Lo que cada nuevo restaurante realmente aporta

No es revenue. No es un caso de éxito.

Cada nuevo restaurante es un **nodo sensor** que alimenta la inteligencia colectiva.

```
Restaurante A reporta merma del 18% en proteínas
Restaurante B reporta merma del 12% en proteínas
        ↓
Pulso detecta: B usa recetas estandarizadas, A no
        ↓
Pulso recomienda a A: "Estandariza recetas. Proyectamos ahorro de $X/mes."
        ↓
A implementa. Merma baja a 13%.
        ↓
El modelo se refuerza. La recomendación se vuelve más precisa.
        ↓
El restaurante C, cuando se incorpora, ya recibe esta inteligencia desde el día 1.
```

Esto no es consultoría. Es **inteligencia operacional colectiva.** La consultoría tradicional no puede hacer esto porque cada consultor trabaja en silos. Pulso unifica el aprendizaje.

## 5. El Onboarding Como Producto, No Como Servicio

El documento anterior describe una implementación de 12 semanas altamente manual. Eso es insostenible y además es un error estratégico: hace que el costo marginal de cada nuevo cliente sea demasiado alto.

### Reemplazar horas de consultor por inteligencia artificial

| Hoy (consultoría manual) | Mañana (AI-powered) |
|--------------------------|---------------------|
| Consultor visita sucursal 2 días para documentar procesos | **Discovery Engine**: IA entrevista al gerente por WhatsApp. Genera mapa de procesos en horas. |
| Consultor escribe manual operativo | **Playbook Generator**: IA redacta SOPs estandarizados basados en el tipo de cocina, tamaño, turnos. |
| Consultor configura workflows uno por uno | **Workflow Factory**: IA genera automáticamente los workflows basados en el playbook. |
| Consultor capacita presencialmente | **AI Trainer**: Videos generados automáticamente + guías interactivas por WhatsApp para cada rol. |
| Consultor audita manualmente | **Continuous Verification**: Fotos con IA evalúan compliance automáticamente. El consultor solo revisa excepciones. |
| Consultor escribe reporte mensual | **Auto-Report**: Dashboard ejecutivo se genera solo. El consultor solo agrega narrativa estratégica. |

### El nuevo onboarding: 4 fases, no 12 semanas


## 9. El Riesgo Existencial: Que La Consultoría Se Coma a La Plataforma

El mayor riesgo del documento anterior es que la consultoría se convierta en la empresa y Pulso quede como soporte interno. Esto no es un riesgo teórico — es lo que pasa naturalmente porque la consultoría factura más rápido, el cliente la entiende mejor, y los ingresos son más visibles.

### Señales de alerta (si aparecen, corregir inmediatamente)

| Señal | Significa que... |
|-------|-----------------|
| Los consultores deciden qué features se construyen | Pulso es soporte, no plataforma |
| El roadmap se llena de "customizaciones para cliente X" | Pulso es una fábrica de software a medida |
| Los datos no se estandarizan entre clientes | Se pierde el activo de inteligencia colectiva |
| No se contrata talento de producto/tech | La empresa es una consultora, no una plataforma |
| El pricing se negocia cliente por cliente | No hay producto, hay proyecto |
| La valuación se hace por múltiplos de consultoría | El mercado te trata como servicios, no como tech |

### Protecciones estructurales

| Regla | Propósito |
|-------|-----------|
| **Nunca construir features que solo sirvan a un cliente** | Mantener la plataforma horizontal |
| **Todo dato de un cliente alimenta modelos que benefician a todos** | El valor colectivo > valor individual |
| **El product team tiene veto sobre customizaciones** | Proteger la integridad de la plataforma |
| **Pricing público, por sucursal, no negociable** | Señal de producto, no de proyecto |
| **Invertir en AI/ML aunque no genere revenue inmediato** | Señal de que creemos en la inteligencia como activo |
| **No facturar por hora de consultor. Facturar por valor entregado.** | Alinear incentivos con plataforma, no con tiempo |

## 12. Una Pregunta Para Cerrar

El documento de consultoría decía:

> "Cada cliente mejora el software."

La versión corregida debería decir:

> **"Cada restaurante que se conecta a Pulso aumenta la inteligencia operacional de todos los demás."**
